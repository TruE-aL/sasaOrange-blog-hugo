{{- /* A card is one entry in a home list: a cover, the meta line, the title and the summary. Where the cover goes is up to width, and the two layouts are deliberately different things: a fixed-height block beside the text from 760px up, a full-width 16:9 frame above it on a phone. The CSS block at the end of ruri.css says why. The picture is written before the text and placed with grid-template-areas rather than moved with `order`, so a no-CSS render and the accessibility tree read in the order the eye does, and the phone layout — where the picture really is first — needs no second copy of the markup. The cover link keeps `tabindex="-1"` and `aria-hidden="true"`: the title below is already the link to the same page, and two tab stops for one destination is a nuisance, not a courtesy. `kind="cover"` asks the image partial for the cover ladder and the `sizes` that describes both shapes, so a 190px block does not download a phone's full-width file and a phone does not upload a desktop thumbnail. The first screenful is fetched eagerly at a high priority. The reveal animation shows those cards a moment after paint, and lazy-loading them would leave the top of the list blank on a slow connection; everything below the fold stays lazy. Which cards are in that first screenful is not something a page can work out about itself here — neither `.Ordinal` nor `.Position` answers reliably for a weighted page inside a section list — so the caller passes `priority` down from the loop index it already has. */ -}} {{- $page := .page -}} {{- $cover := "" -}} {{- if ne $page.Params.cover false -}}{{- $cover = partial "cover.html" $page -}}{{- end -}} {{- $priority := .priority | default false -}}
